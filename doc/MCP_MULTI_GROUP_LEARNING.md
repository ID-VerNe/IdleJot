# 按账号和群共享本地知识

MCP 连接仅是访问凭据。表达、黑话、计数、人工修订、禁用、学习偏好和预算按 `qq:机器人账号:group:群号` 保存。一个连接可以在多个已授权群同时学习；不同连接访问同账号同群时读取同一份知识。

## 使用

在已连接的 Agent 中指定账号与群开始聊天即可。每个群仍有自己的持续聊天会话，等待、规划和学习阶段使用对应的 `session_id`。同账号同群仍只允许一个活跃聊天会话，避免重复发言。

不开始聊天也可以调用 `get_chat_learning(conversation_id="111:group:222", records=true)` 读取这个账号群的本地知识；账号和群使用已发现的真实会话编号。示例编号仅为合成数据。原来的 `get_chat_learning(session_id=...)` 保持兼容，两种目标参数只能选一个。读取不会启动学习或收集消息，实时服务离线时仍可读取已经保存的知识。

一个连接访问多个群无需重新建连接、重新导入或第二个学习开关。授权仍限制账号、群及日期，撤权后不能读取或提交；新增工具入口不扩大旧凭据权限。

## 数据与任务

- 继续使用 `data/mcp-language.sqlite3`，不清空、不重算累计次数、不修改人物卡。
- 旧 `pins`、`contexts` 表暂保留用于回退，新代码不使用它们限制群范围。
- 运行和任务仍核对账号群、当前授权、会话及连接代际；另一个群的来源、任务或结果会被拒绝。旧 `context_id` 参数可复用，但不能替代任务凭据。
- 停止一个群不会取消其他群的任务。暂停某群学习会保留该群知识，其他群不受影响。服务重启取消未完成任务，保留已落库条目、人工修订和偏好。
- 本地库隔离不等于宿主模型上下文隔离；宿主自行管理上下文。本轮不改变学习算法、阈值或模型调用方式。

## 可复现验收

在项目 Python 环境运行：

```powershell
python scripts/check_mcp_multi_group_learning.py
python scripts/check_mcp_language_learning.py
python scripts/check_mcp_language_integration.py
python scripts/check_mcp_auto_learning.py
python scripts/check_mcp_jargon_pipeline.py
python scripts/check_reader_install.py
```

安装态可使用包内 `runtime/python.exe` 运行同样的学习测试，附加 `--package <Tulpa目录>`。测试都使用临时数据与模拟 OneBot，不发送真实 QQ 消息。

新增贯通测试使用同一凭据、两个群、20 条合成群友消息、6 个模拟模型阶段；覆盖并发去重、旧绑定兼容、来源交叉提交拒绝、按群暂停、同群换凭据、重启、撤权、未知目标拒绝、停止聊天后的本地读取及真实 MCP HTTP 协议。重复消息编号在两个群中生成不同来源标识，知识与计数各自隔离。此测试不证明真实模型的学习质量。

## 回退

更新本地运行目录前保存程序及完整用户状态备份。程序改动仅为 Python、前端说明和文档资源，不需更换账号、人物卡或学习库。回退时先退出 Tulpa，恢复备份中的改动程序文件即可；如需整体恢复数据，应另备份升级后新增记录，避免覆盖新积累。旧程序仍会执行它原有的连接单群限制。
