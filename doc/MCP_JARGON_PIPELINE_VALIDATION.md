# 黑话独立学习链路验收

本次参考 MaiBot 固定提交 `f9ec3670a3638d6a4708ee5253f7ffe2838c9415` 的算法，自行实现专用提词、独立任务及阶段式释义。没有复制 GPL 源码或提示词；继续只学习当前授权机器人账号、当前群的新鲜真实群友消息。人物卡、模型输出、工具结果、历史数据库均不作为来源。

## 改动与边界

- 专用 `extract_jargon` 阶段要求词、来源、原文、类别及依赖群语境的理由，结构不合格时拒收；表达审核失败不再阻塞提词计数。
- 每批独立表达和黑话任务，轮转调度，冷却任务让出位置。释义里程碑仍为4/8/25/100，同词每批只计一次，最近50词补漏、最多10条已确认黑话供理解使用均保留。
- 带语境释义须提供可验证群友原文；证据不足只执行这一阶段，保留此前有效结果、等下一里程碑。普通含义一致时不再作为黑话注入，旧解释仍保留供复核。人工修订优先。
- DSH 等顺序外部宿主无法由 Tulpa 清除上下文。通常词义阶段并非真正盲测，始终返回 `isolated=false`。本次没有实现隔离上下文适配器，没有新模型/API/密钥；也不据模拟结果声称真实释义质量提高。
- 典型批次从2个增至3个现有 Agent 阶段；聊天优先和默认每小时20阶段预算不变，预算耗尽后等待恢复，不忙轮询。
- Schema 仅增加 `jobs.queue_order` 与索引；旧库记录保留，旧未完任务在重启边界取消。清空真实库是本次用户另行明确授权的本地操作，不是升级默认行为。

## 人工体验

1. 更新后重新连接 MCP，并开新 Agent 对话，避免旧宿主上下文继续携带已清空的学习内容。照常要求在指定群持续聊天。
2. 只积累启动后的群友消息；至少10条且满30秒形成一批。表达和黑话分别学习，沉默不退出循环。
3. 查看学习记录：普通词不应仅因常见而被收录；黑话先是候选，4个有效批次命中后才有首次释义机会。模型漏提的近期已知词仍会机械补计。
4. 已确认且有释义的词只有出现在当前关联消息中才作为理解参考；不要求模型主动刷黑话。检查详情会明确写“顺序自检，非独立核验”。

真实模型是否更准确须由后续群聊样本评价；本次自动验收只证明工程链路和边界。程序备份、清库前一致性数据库快照与人物卡哈希放在本机私有报告目录，不随源码或发布包上传。回退前彻底退出 Tulpa，恢复备份程序；如需恢复旧学习记录，再单独恢复清库前 SQLite，勿覆盖更新后新积累而不另备份。
