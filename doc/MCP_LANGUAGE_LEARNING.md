# MCP 实时语言学习

本功能只作用于持续 QQ 群聊 MCP。程序保存有限的实时材料，外部 Agent 分阶段提取、审核表达和解释黑话。没有模型训练、人物画像、历史库回填、新 API Key 或后台内置模型。原人物卡不改写。

## 开启与操作

1. 保持 OneBot、Tulpa 和已连接的 Agent 运行。在专用 Agent 对话中正常提出“用小鲸鱼2号在某群持续聊天”，就会同时开始观察与学习。无需另外启用学习、抄学习口令或手动领取阶段。
2. Tulpa → 连接外部 Agent 只保留一行 **群聊与学习 → 管理**入口。持续聊天由用户在 Agent 对话中发起；这里不提供开始或重开会话按钮。
3. 管理面板中的群卡显示机器人 QQ、群号、潜水/准备回复/已停止，以及积累中/学习中/等待 Agent/预算暂停/学习关闭，可停止正在运行的会话。**查看学习记录**查看表达和群内用语；高级设置可暂停当前账号群的学习或调整每小时阶段预算。此前明确暂停的选择会保留，新连接不会解除暂停。
4. 停止后原库保留。原账号原群重新开始并通过当前授权核验即可接续，无需第二开关。同一连接可用于多个已授权群；各群使用各自会话，宿主自行管理模型上下文。

通过自检的表达默认进入可用范围；不足 **10 条**时仍不注入聊天，界面显示例如“4/10，继续积累后才用于聊天”。黑话的“待观察”不等于已掌握。提取和自检确实分阶段调用，但顺序宿主可能记得前文，不能称为独立核验或质量保证；高级详情保留 `independence=degraded`。已取消额外的“允许顺序审核结果”开关。

没有活跃宿主或宿主结束任务时，服务器只积累有界材料，显示等待 Agent；不会自行启动模型。升级后重启 Tulpa，并在客户端重新连接 MCP 以刷新工具说明。只需正常开始持续聊天，不需要知道领取工具名称。宿主是否持续遵循循环仍由宿主控制，Tulpa 无法强制一个已退出的 Agent 继续推理。

## 边界和存储

- 服务端从当前已核验 OneBot 连接和聊天授权解析 `qq:机器人账号:group:群号`。模型工具不接收账号或群号参数。
- MCP 连接只承担访问授权，不绑定学习库。一个连接可以在多个已授权群同时持续聊天和学习；每个会话、任务、来源及提交结果仍绑定自己的账号和群。不同连接访问同账号同群时共用知识、人工修订、暂停偏好与预算，不重复建库。原有群范围、日期、账号和撤权检查继续生效。
- 库和暂停偏好属于平台 + 机器人 QQ + 群，独立于 session/grant。同账号同群的新授权通过现有权限和来源核验后接续；旧撤销连接仍不能访问。换账号或群看不到旧库、计数或诊断。
- 外部宿主自行管理模型上下文；Tulpa 不再以宿主上下文标识限制连接访问多个群。学习阶段仍如实标注顺序自检，不声称独立核验。
- `data/mcp-language.sqlite3` 是单独本地 SQLite。库、偏好和预算按账号群保存；观察、lease 和在途任务仍按当前授权、会话、连接代际隔离。原聊天库不读取、不迁移。迁移此文件时，运行中使用 SQLite backup，不能仅复制活动文件而遗漏事务。
- 默认缓冲 40 条、每批最多 20 条、至少 10 条；首次从开始/恢复学习起计时，后续从上次封批起至少 30 秒。收到消息及服务端 0.5 秒时钟都检查封批，不依赖 claim 或第 11 条消息；领取端也重检同一状态。材料被封批后从观察缓冲消费，原始消息 ID + 时间 + 账号群形成有界去重账本，跨 session/grant 重投不会重复计数。
- 20 条一批用于保留短段对话的前后文；40 条缓冲可容纳两批突发输入，同时受字符预算约束。这是首版的有限成本默认值，尚未通过大规模群聊调优。
- 原始证据最多 24 小时、每个授权分区最多 100 个有原文的批次，先触及的边界生效。黑话保存来源引用，需要时从有限批次还原前后各 3 条，不把每个词的上下文重复复制到永久库。清理在访问分区或下次启动时执行；程序关闭期间不会运行清理进程。
- 抽象表达、黑话和去重元数据长期保留。停用、切号、断线均不删除库；删除整个学习库属于另行管理操作。
- 断线、停止、撤权、进程重启均取消未完成任务和待注入候选。迟到结果拒绝；重启恢复的是已完成记录和去重账本，**不自动续跑旧连接的半成品任务**。黑话的新推断也只取当前授权、会话及连接代际的有效实时证据，不把旧原文带入新宿主上下文。

## 调度和实际模型调用

工具：`get_chat_learning`、`claim_chat_learning`、`submit_chat_learning`、`select_chat_expressions`。自动循环使用现有 `wait_chat_messages`：消息 → Planner（允许 silence）→ 确认进度并等待；或 `learning_ready` → 按返回的 `next_call` 领取一个阶段 → 分次模型判断和提交。claim 返回 `task` 时完成该阶段并沿 `task.submit_call` 提交；claim/submit 附 `updated_chat` 时直接处理其中消息与批次；未领取任务或已提交且无附带聊天时回到等待。服务端阻止连续领取绕过阶段边界；旧 `context_id` 参数继续兼容，但不再参与群或库的绑定。

领取前有输入时不领取任务；提交时先保存原学习结果，再交付已有输入。`updated_chat` 复用等待包：`messages`、`input_batch`、`materials` 及其图片映射；完整可规划批次的内外 `next_call` 均指向规划，确有分页才继续读取。读取不确认消息，不把历史上下文或发送回声当新输入，手动同账号发言仍保留。暂缓决定仍按原 WAITING 规则，到期或新输入才重新决定。交接仅在工具边界非阻塞检查，正常无消息继续原长轮询；不立即领取下一学习阶段。

材料展开和图片准备在学习锁外执行，沿用授权、取消和限额。学习结果保存后交接失败时，原 `state` 回执保持，`chat_error=handoff_unavailable` 表示聊天材料未交付，不代表学习未提交；不会返回失效的聊天链接或消息、图片。可按原 lease/result 幂等核对，已停止或撤权的会话仍拒绝后续访问。外部模型正在执行的学习请求不能中途抢占，只在领取与提交边界让出；这不是所有客户端固定两次模型请求的保证。

`get_chat_learning` 接受 `session_id` 或 `conversation_id` 二选一。后者使用 `list_chat_groups` 返回的 `账号:group:群号`，可以直接读取已授权账号群的本地知识，不必先开聊天或连接实时事件；`records=true` 返回少量条目。读取不启用学习、不启动采集。每次仍验证当前凭据、账号群和日期范围。返回 `library_key` 明确所属库；任务领取也返回这个字段。

升级不清空学习库、不累加迁移计数。旧 `pins`、`contexts` 表暂保留用于回退，但新代码不再读取或更新其中的单群限制。未完成任务仍按停止、撤权及重启边界取消，已落库知识继续保留。

就绪状态同时核验权限、预算、冷却、lease 和聊天队列；pending 数量不代表可领取。wake 标识由任务、阶段和版本派生，原子 lease 防双领，重复提交幂等。领取后必须回到等待接口才能推进下一阶段；新消息和 reaction 通知优先返回，READY/SENDING 聊天工作优先。不发话也要观察、确认进度和等待，silence 不是停止。

一个表达批次通常需要 **2 次模型调用**：

1. `extract`：3–5 条表达（无可靠材料可空），只提交 `expressions`。表达必须描述**来源群友实际说话的形式**，同时提供本批 `source_id`、逐字 `evidence_quote`、原文可见的 `surface_form`（可用 `{对象}` 等变量槽位）及 `form_type`。不是把群友的话当刺激，再总结机器人应该怎样回应。旧客户端的空 `jargon=[]` 仍可接受，非空旧词条须按独立任务重新处理。
2. `review`：另次调用逐项核对群友表达、原文支持、非应对策略、去除人格仍成立及隐私；理由须指出原话的语言特征。“符合人格”“本轮实际做法”不能作为接受理由。接受的完全相同条目每批计数一次。

程序会验证原话确实属于所引来源，语言模板固定部分在原话中存在，检查项均为明确布尔值，并拦截已知的“保持沉默、不插话、顶回去”等策略型结果。模板支持用词、句式、标点和双关；普通群友说“别太离谱”不因含否定词而被禁止。字面验证和有限规则不能判定所有语义，最终自检仍可能出错，不能宣称已实现独立核验。

固定部分可短至一个字或一个 emoji，例如 `{名词}吗`；只含变量的空模板仍拒绝。模板不使用斜杠备选和虚构省略号，除非原话确有这些字符。校验失败返回具体的 `field`（例如 `expressions[1].surface_form`）和原因，不回显私人内容；错误定位用于纠正本次提交，不能伪造来源或把失败结果算作成功。

此前没有群友语言证据的旧表达原样保留，界面标为“旧记录待复核”，不再进入回复候选；原启停状态及计数不改。后续实时学习遇到有证据的相同条目才会补足证明，**不会自动重读旧群聊或批量把旧记录升级为通过**。新通过的表达仍须达到 10 条才开始提供候选，不另加启用开关。`expression_grounding` 保存来源编号、批次、模板和引文哈希，不长期另存逐字引文；原文仍受既有 24 小时证据期限约束。

提取明确返回空表达列表时没有待审核表达，跳过空审核，节省一次调用。

同一批真实群友材料还产生独立的 `extract_jargon` 任务。专用提示筛选需要群内语境或含义不清的短词，排除普通词、含义明确的通用网络词、人名、机器人名、命令和纯符号。每条需 `term/source_id/evidence_quote/category/context_dependency/checks`；程序校验来源、逐字引用、词形和检查项。语义判断仍由当前 Agent 做，结构校验不保证模型判断正确。最多 30 条，没有可靠词条就返回空；不再等待表达审核才累计黑话。

各阶段按持久队列轮转；已达里程碑的释义可在表达仍有待办时入队，单词不会并发运行多个里程碑。冷却中的任务不阻塞其他就绪任务。每次仍只领取一个阶段，提交后按 next_call 先处理附带聊天或回到 wait，聊天 READY/SENDING 优先，沿用预算、lease、撤权和停止边界。正常有表达批次需要“表达提取、表达自检、黑话提取”3 个当前 Agent 阶段（此前2个）；没有新增模型服务或 API。离线宿主不会自动学习。

黑话新候选 `is_jargon=false`、释义为空。命中批次累计到 **4、8、25、100** 时，另外最多需要 **3 次模型调用**：带群友证据解释 → 通常词义自检 → 比较。第一步必须提供可逐字校验的 `usage_evidence`；证据不足立即结束，不继续消耗后两次调用，同一命中数不盲重试，保留旧释义。比较须有充分证据且意义不相同时才确认；普通含义一致时不再注入该词，但保留旧释义供后续复核。一次计数跨多个里程碑时只推断当前计数一次；成功比较到100后结束自动推断。人工释义优先，进行中的自动结果也不能覆盖。

黑话批次入账时，除模型提取的新词外，也用当前账号群最近 **50 个**启用、非人工词条匹配本批原始群友文本，补上模型漏提的已知候选。中文用子串，其他词用文字边界，大小写归一；例如 `cat` 不会因 `concatenate` 而命中。合并后每词每批最多增加一次计数，并保存本批可核对的来源编号。重试、并发重复提交、模型提取与程序同时匹配均不重复累计。停用或人工释义条目不继续自动累计。程序匹配不直接确认释义，也不增加模型调用。

最近候选从已有作用域索引有界读取，重启或新授权核验通过后可继续补漏；不回读历史库，不读取别群/别账号原文，不用机器人和工具输出。只有合法学习批次完成入账时才执行补漏，提取失败不计数；有表达时仍先完成自检。返回的 `jargon_observation` 只报告模型词数、检查的缓存词数、补漏词数和新增批次命中数，不包含原文。`jargon_cache_terms` 可设为 0 关闭补漏，默认 50、最大 200。

提取和审核工具领取/提交是不同阶段，要求不同 `invocation_id`；这可以阻止误复用调用编号，**不能从服务端证明模型真的推理了两次**。宿主应实际分次调用。本版没有可验证的隔离子模型适配器：即使兼容阶段名 `without_context` 的本次材料只有词，顺序对话仍可能看过前文。因此明确返回 `context_verification={mode: sequential_self_check, isolated: false}`、保留 `independence=degraded`，界面显示“顺序自检，非独立核验”。不以提示词、换 invocation_id 或宿主自报布尔值伪装隔离，也不能保证模型不受前文影响。

默认每个账号群每小时最多领取 20 个阶段；创建新连接不会重置预算。每阶段最多 2 次尝试，重试至少等待 15 秒，lease 120 秒；每会话一个领取，全局最多三个。预算、lease 占用、重试冷却时 wait 保持等待，默认连续调用使用 150 秒有界长等待；到期返回 idle 后继续 wait，不做零任务忙循环。按默认等待约每分钟 0.4 次空闲调用，服务端本地时钟不产生模型调用。

学习期间出现新消息，在该次模型阶段返回后的安全边界优先接话。程序不能打断外部宿主正在执行的模型调用；120 秒 lease 只使迟到提交失效，不代表能强制取消模型或保证最长 120 秒后回话。实际响应上界取决于宿主超时和生成时间。

READY 回复超过原发送 TTL 后不再阻塞学习领取；发送中的队列仍优先。这里只判断学习调度，不修改原回复队列或消息新鲜度算法。

默认每条材料最多 800 字符、批次 16,000 字符；审核或比较输入上限为该值两倍（含候选/两份释义）。这不是 token 计费估算；状态页报告实际领取次数和序列化材料字符数，不虚构模型账单。

## 回复时使用

- 仍先 `plan_chat_reply`。只匹配该计划关联的已读真实他人文本，不能扩大到未读页或历史库。
- 可用表达不足 10 条不出候选；没有 embedding 配置时按 count 加权、不放回抽样：全库最多5条，计数大于1的高频池至少10条时另取最多5条，合并去重后至多10条。候选固定在该计划，不因轮询反复换样。有候选的文字计划将顶层 `next_call` 指向 `select_chat_expressions`，模型须选择 0–5 条后组织回复，也可用空列表明确全部不选。发送入口和旧单条发送工具均检查此步骤，缺失时返回 `expression_selection_required`，尚未发送。
- 沉默/等待、纯表情/回应、无候选、未到 10 条门槛及学习暂停不要求额外选择调用。混合计划实际只发表情时也可直接完成。相同选择幂等，改变已完成的选择会拒绝；人工停用条目后旧候选失效，若仍有足量候选须重新选择，不能沿用已停用内容。选定返回只包含选定参考和匹配黑话，不再重复整个候选集。
- 计划回执的 `expression_selection` 记录候选/已选 ID、参考载荷哈希、准备时间及明确不用/不适用的原因，跟随发送成功、失败或未知的真实回执。标记 `tool_result_prepared`，宿主实际注入与模型措辞采用保持 `unverified`；不能将“已选”当作“模型确实学会或使用”。未选候选此前可能已在宿主上下文中出现，程序不能清除外部模型记忆。记录不保存额外原话，沿用聊天计划的保留和授权边界。
- 当前 MCP 没有已有 embedding 服务配置，因此本版实际使用加权路线。存储层有受作用域约束的可选检索器接口并用 fixture 验证最多 50 条；这不代表已经上线向量服务，也不会偷偷调用新的服务。
- 黑话仅用大小写归一后的子串匹配，最多 10 条有释义且确认/人工设置的词。候选、空释义、禁用记录不作为确定知识。
- 人物卡优先，学习只作本轮可选数据。不会修改原小鲸鱼或小鲸鱼2号，不自动复读、不强制发言、不绕过原来的等待、目标、新鲜度、权限和气泡队列。

配置可选放入 `data/mcp-language-policy.json`，修改后重启；默认不需文件：

```json
{"window_messages":20,"buffer_messages":40,"interval_seconds":30,"evidence_seconds":86400,"evidence_batches":100,"message_chars":800,"material_chars":16000,"lease_seconds":120,"hourly_calls":20,"max_attempts":2,"retry_seconds":15,"jargon_cache_terms":50}
```

无效配置会停止学习并报错，不能静默降低安全门槛。局部覆盖字段可用；观察门槛 10 条、最低间隔 30 秒、全局并发 3 不允许越过。
